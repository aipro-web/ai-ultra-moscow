Какие документы действительно нужны агенту

Начинаем с вопросов, которые компания уже получает: условия покупки, состав услуги, сроки, ограничения, поддержка и передача специалисту. Под каждый вопрос находим утверждённый источник. Архив переписки полезен для поиска типовых ситуаций, но сам по себе не становится достоверным справочником.

Коротко: Проектирование базы знаний для AI-агентов: документы, поиск RAG, актуальность, доступы, ссылки на источники и ответы при нехватке информации.

В каждом документе фиксируем владельца, дату действия, продукт и область применения. Старый прайс и новое коммерческое предложение могут противоречить друг другу. До подключения поиска нужно решить, какой источник имеет приоритет и какие сведения агенту запрещено использовать.

Результат этого этапа — список тем, источников и пробелов. Если правила ещё нет, мы отмечаем необходимость решения со стороны компании, а не просим модель придумать его.

Как работает поиск по документам — RAG

RAG — подход, при котором система сначала ищет подходящие сведения во внешних материалах, а затем передаёт найденные фрагменты модели для подготовки ответа. Документы остаются отдельным источником: обновление базы не обязательно требует переобучения самой модели.

Поиск и формулирование ответа проверяем отдельно. Система может найти неподходящую редакцию документа или пропустить исключение, даже если текст ответа звучит уверенно. Поэтому полезно сохранять ссылки на использованные источники и тестировать вопросы, для которых в базе нет ответа.

RAG не гарантирует отсутствие ошибок. Для стоимости, сроков и условий договора важны правила цитирования, ограничения на самостоятельные выводы и передача человеку при противоречиях.

Как разделять доступы

Публичные условия, внутренние инструкции и клиентские документы не должны попадать в один неограниченный поиск. Доступ проверяется до выдачи материалов модели. Пользователь должен видеть только те сведения, на которые у него есть права.

Для многопользовательского продукта отдельно проверяем изоляцию клиентов. Просьба «покажи документ другой компании» не меняет разрешения. Веб-страницы, письма и загруженные файлы считаются данными, а не командами, которые могут отменить правила системы.

Как обновлять знания без противоречий

За каждой темой закрепляем ответственного. Новая версия проходит утверждение, после чего старая исключается из активного поиска или явно помечается как архивная. В журнале сохраняется, какая версия была доступна в момент ответа.

Если меняется важное условие, повторно проверяем связанные вопросы: прямой запрос, уточнение, сравнение и формулировку с ошибкой. Это позволяет заметить ситуацию, когда основной ответ обновился, а старое исключение осталось в другом документе.

Как выглядит проверяемый результат

  • Для типового вопроса найден правильный действующий источник.
  • Ответ не добавляет неподтверждённых условий.
  • На неизвестный вопрос агент честно сообщает о недостатке данных.
  • Пользователь не получает закрытые документы другой роли или клиента.
  • Компания может обновить материал и повторить проверку.

Для начала пришлите перечень документов и несколько типовых вопросов без закрытых данных. Обсудим, какие ответы можно автоматизировать, где потребуется уточнение и что лучше сразу передавать специалисту.

Как проверяем результат

На старте выбираем несколько показателей, которые можно сравнивать до и после изменения процесса. Для этой задачи обычно полезно смотреть на:

  • Точность выполнения согласованных сценариев.
  • Доля обращений, завершённых без ручной рутины.
  • Количество ошибок и эскалаций.

AI-агент должен быть проверяемой частью процесса, а не отдельным «умным окном». Поэтому вместе с промптом проектируются источники данных, права, журналирование, тесты и ручной fallback.
